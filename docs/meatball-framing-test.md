# Pittsburgh Italian Pack: meatball framing test

Same offer on both pages. $189, free shipping, and an identical box:
5 lb sweet sausage, 5 lb hot sausage, 2 lb hand-rolled meatballs, one of Lil's
sausage rolls. Same Shopify product, same zone variants, same price. The only
difference is how the meatballs are described.

| Version | Framing | Preview path |
| --- | --- | --- |
| A / control | "Includes 2 lb" — existing wording | `/shop/pittsburgh-italian-pack?preview=1` |
| B / free | "FREE 2 lb … yours free with the box" | `/shop/pittsburgh-italian-pack-free?preview=1` |

B changes the meatball lines only: hero figcaption, buy lead, manifest row,
trust strip, includes card, the six-dinners stat, the closing CTA paragraph,
and the page title/description. It also lists the sausage roll above the
meatballs in the manifest and the includes cards, so the free item reads last. Everything else — photography, price blocks,
guarantee, FAQ, schema price — is byte-identical to A. This is a wording test,
not an offer test; do not change one side's contents, price, or shipping.

`site/shop/pittsburgh-italian-pack-free.html` is generated by hand from the
control page. If you edit the control's layout mid-test, mirror the edit into B
in the same commit or end the test — a layout difference invalidates it.

## Routing and measurement

- Campaign URL: `https://riccisausage.com/shop/pittsburgh-italian-pack`. Same
  URL for all ads and links. B is noindex and exists only for the test.
- `js/meatball-experiment.js` runs before paint/analytics. Random 50/50
  allocation. A first-party cookie (`ricci_meatball_v1`, separate from the
  grill box's) holds the anonymous browser ID and variant for 90 days, shared
  across www and apex. Returning browsers stay put.
- Redirects preserve query strings and hash. `?preview=1` bypasses assignment
  and custom event tracking; preview visits never change an existing assignment.
- Non-production hosts, common bot agents, unavailable crypto, and browsers
  refusing the assignment cookie do not enter the experiment. No-JS visitors see
  the directly requested page and are not counted.
- Count the first visible page exposure, then the first Buy click. The CTA here
  is `[data-buy-now]`, not an outbound link: `js/buy-now.js` cancels the click,
  resolves the shipping zone, then navigates. `js/meatball-events.js` therefore
  counts clicks on `[data-buy-now][data-id="pittsburgh-italian-pack"]` and
  ignores `defaultPrevented`. The phone CTA is not a conversion.
- Events post to the CRM with `text/plain` and keepalive/beacon, never delaying
  checkout. `crm.js` supplies the backend base URL.
- The CRM deduplicates by experiment + browser ID, keeps the first observed
  variant, and counts no more than one click per browser. Out-of-order click
  delivery implies exposure, so click rates can't exceed 100%.
- Results: `/admin/experiments`, behind existing admin auth. Both this test and
  the grill box render there — visitors, clickers, traffic share, rates, and
  per-rate Wilson 95% intervals. No automatic winner or traffic shifting.

## Launch order

1. Deploy the CRM first. `initExperiments` moves the grill box's rows into the
   shared `experiment_visitors` table (the old table's variant CHECK couldn't
   hold new variant names) and drops the old one. Copy then drop happens in one
   transaction; grill-box history is preserved. Take the usual volume snapshot
   before deploying anyway.
2. Check `/admin/experiments`: the grill box's existing numbers should be
   unchanged, with two empty meatball rows below them. Validate the public
   endpoint against a local test database, not fabricated production events.
3. Review both pages at desktop and mobile sizes. Repository rules ask the owner
   to do visual verification; no automated browser screenshots.
4. Publish the static site. Do not publish before the CRM endpoint is deployed.
5. Point ads at the campaign URL **without `preview=1`**. Agree on duration and
   sample target before judging. Two variants split traffic evenly, so this
   needs less traffic than the four-way grill box test — but small counts are
   still exploratory.

Buy-click rate measures purchase intent, not sales. If B wins on clicks, confirm
in Shopify that orders followed; "free" framing can pull clicks that don't close.
Cookie deletion, multiple devices, blocked tracking, unrecognized bots, and
failed delivery affect counts.

For a new test, change the experiment ID and cookie key in the client and add a
new spec in the CRM. Don't edit a running variant and pool it with old results.

## Checks

```
node tools/check-pages.mjs site/shop/pittsburgh-italian-pack.html site/shop/pittsburgh-italian-pack-free.html
node --test tools/meatball-experiment/browser.test.mjs
```

CRM implementation lives in `../riccis-crm/src/experiments.ts` (now a registry of
experiment specs), with the generic route `/api/experiments/:slug/events` and the
protected dashboard mounted in `src/index.ts`. Its checks are
`bun test src/experiments.test.ts` and `./node_modules/.bin/tsc --noEmit`.
